# 案例

三个真实案例，来自同一条产品线（一个把 PSD 文字层批量替换成多语言、再产出多语言详情页的内部工具）。

公司名、产品型号、客户数据已移除；路径、常量名、命令与退出码保留原样——**因为可核验性就建立在它们上面**。

| 案例 | 一句话 | 它证明了什么 |
|---|---|---|
| [01 一条测试全绿的护栏，从 HTTP 路径永远到不了](01-guard-that-could-never-fire.md) | 护栏是真的，测试是真的，绿是真的，防护是零 | 门在场 ≠ 门被走到 |
| [02 一个月后，同一份审查结论自己过期了](02-conclusion-that-expired.md) | 结论有保质期，但没人回去给它贴日期 | 报告必须带基线 SHA 与取证日期 |
| [03 报告自己声明「未跑任何测试」](03-declaring-what-you-did-not-do.md) | 敢写"这四条没做"的报告，比全绿的报告更可信 | 静态审查必须自报边界 |

## 读法

三个案例是**递进**的，不是并列的：

- **01 讲怎么发现**：一条写在代码里的护栏，怎么被证明是死的
- **02 讲怎么失效**：01 里那条结论，一个月后为什么不成立了
- **03 讲怎么诚实**：01 那份报告，凭什么在没跑测试的情况下仍然可信

只读 01 会以为这是一份"抓 bug 的教程"。读完 02 和 03 才会明白：**对抗式审查的价值不在抓到了什么，在于它知道自己抓到了什么、没抓到什么、以及那些结论什么时候会过期。**

## 关于脱敏

三个案例都保留了这个程度的细节：

- ✅ 保留：`file:line`、常量名、函数名、命令原式、真实退出码、代码片段
- ✅ 保留：时间线、版本号、决策记录
- ❌ 移除：公司名、品牌名、产品型号、SKU、客户文案、凭据、服务器地址

原则很简单：**去掉"这是谁的东西"，保留"这是怎么查出来的"。**

如果连 `file:line` 和命令都要抹掉，案例就退化成经验谈——那是脱敏的代价，不是脱敏的目的。
