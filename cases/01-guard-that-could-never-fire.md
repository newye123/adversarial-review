# 案例一：一条测试全绿的护栏，从 HTTP 路径永远到不了

> 来源：真实内部项目（多语言 PSD 批处理工具）。路径与常量名保留原样，公司名与产品型号已移除。
> 这份案例的关键不是"发现了一个 bug"，是**发现了一个测试全绿但根本没在守东西的护栏**。

## 现象

官网公开承诺「单次最多 12 个目标语种」。用户提交 12 个语种，拿到的报价是 10 个语种的。

没有报错，没有提示，没有降级告知。用户以为自己买了 12 个。

## 一开始以为

第一反应是"官网文案写错了"或"上限就是 12，只是报价算少了"。

这两个方向都错。**真正的问题在上游**：请求在到达业务逻辑之前，就被静默截断了。

## 取证

四行代码，两个常量，一条护栏：

```bash
$ grep -n "MAX_LANGUAGES" src/app/api/workbench/execution-batches/quote/route.ts
16:const MAX_LANGUAGES = 10
47:  .filter((c) => isSupported(c))
48:  .slice(0, MAX_LANGUAGES)
```

```bash
$ grep -n "MAX_LANGUAGES_PER_BATCH" src/lib/server/execution-batch.ts
51:const MAX_LANGUAGES_PER_BATCH = 10
120:  if (languages.length > MAX_LANGUAGES_PER_BATCH) {
121:    throw new Error('BATCH_LANGUAGES_EXCEEDED')
122:  }
```

读出来的链条是这样：

1. 官网说 12
2. 路由层 `MAX_LANGUAGES = 10`
3. `.filter(...).slice(0, MAX_LANGUAGES)` —— **无报错、无提示、无降级告知**，12 个进来，10 个出去
4. 服务层 `MAX_LANGUAGES_PER_BATCH = 10`，超过就抛 `BATCH_LANGUAGES_EXCEEDED`
5. **但因为第 3 步已经截断，第 4 步这条护栏从 HTTP 路径永远走不到**

## 关键：这条护栏有测试，测试是绿的

`BATCH_LANGUAGES_EXCEEDED` 有 smoke 覆盖，跑起来显示通过。

**它测的是直调 service 的路径**——直接构造一个 12 元素的数组传给 service，护栏当然抛错。

但真实用户走的是 HTTP：请求先经过路由层，被 `.slice()` 截成 10 个，到 service 时**长度永远不超过 10**。

于是：**护栏是真的，测试是真的，绿是真的，防护是零。**

这就是典型的假绿——不是测试写错了，是测试**测的不是用户走的那条路**。

## 结论

| 项 | 判定 |
|---|---|
| 官网文案 | 12，正确 |
| 路由层上限 | 10，**错** |
| 静默截断 | `.slice(0, 10)`，**违反项目红线「不得引入任何静默降级」** |
| 服务层护栏 | 代码正确，**但不可达** |
| 护栏的测试 | 通过，**但是假绿** |

修复方向不是"把 10 改成 12"（那只是让症状消失），而是**把截断改成显式拒绝**：

```
超过上限 → 返回 BATCH_LANGUAGES_EXCEEDED + 中文提示「单次最多 N 个目标语种」
```

让用户知道发生了什么，比让用户以为成功了要好。

## 代价

用户提交 12 语种，拿到 10 语种的报价，且不知道自己少了两个。如果下游还按语言集合做计费对账，会再撞一次 `BILLING_LANGUAGE_SET_MISMATCH`——但那时报的是内部错误码，用户更看不懂。

## 可迁移的判据

> **门在场 ≠ 门被走到。**

审查任何护栏时，问三个问题：

1. 这条护栏的**入口**是什么？HTTP 路由、CLI、还是直接调 service？
2. 它的测试**从哪个入口进**？和用户走的是同一个吗？
3. 在它之前，有没有代码会**先一步把非法输入变成合法输入**？

第 3 问最容易漏。任何 `.slice()` / `.filter()` / `.slice(0, N)` / `.take(N)` / `Math.min(x, N)` 出现在护栏之前，护栏就可能是死的。

## 对应的检查器规则

- `E005`：finding 必须给 `file:line` 或命令原式——本案例的结论完全建立在 4 个行号上
- `E006`：说「护栏不可达」这种否定式断言，必须附命令和退出码
- `E004`：防回归测试不能写「无」——本案例的修复必须带一条**从 HTTP 入口进**的测试
